# MindUnlock — ماتریس اجرایی تکمیل محصول

> آخرین بازبینی: 2026-11-13  
> هدف: نسخه کامل شخصی مطابق خواسته‌های فعلی؛ معماری آماده توسعه عمومی، بدون الزام به انتشار عمومی در این مرحله.  
> قاعده وضعیت: «انجام‌شده» فقط با کد قابل مشاهده و آزمون مرتبط ثبت می‌شود. موفقیت CI جایگزین آزمون روی دستگاه واقعی نیست.

## 1) معیارهای محصول قطعی

- [x] محصول نهایی MindUnlock است؛ MindRebuild فقط منبع ایده و قابلیت‌های قابل انتقال است.
- [x] استفاده شخصی در اولویت است؛ هسته باید Local-first و Offline-first بماند.
- [x] داده‌های شخصی از محتوای آموزشی جدا نگهداری شوند.
- [x] فارسی، RTL و تقویم شمسی در تجربه کاربری پشتیبانی شوند.
- [x] صفحه «درباره ما» با مشخصات حرفه‌ای سازنده و معرفی اصول محصول اضافه شد؛ اطلاعات دانشگاه و مشتریان عمداً درج نشده‌اند.
- [x] تم روشن به‌عنوان پیش‌فرض نصب تازه تنظیم شد؛ انتخاب ذخیره‌شده کاربر در اجراهای بعدی حفظ می‌شود.
- [x] قابلیت‌ها ماژولار، قابل آزمون و قابل توسعه باشند.
- [ ] هیچ قابلیت برنامه‌ریزی‌شده‌ای پیش از پیاده‌سازی و آزمون، کامل اعلام نشود.
- [ ] یکپارچگی جریان‌های کاری بین ماژول‌ها تکمیل شود.

## 4) تعریف Done

هر قابلیت فقط وقتی «انجام‌شده» می‌شود که:
1. کد واقعی در شاخه توسعه ثبت شده باشد.
2. منطق اصلی تست واحد یا تست یکپارچه مناسب داشته باشد.
3. Migration و Backup در صورت اثرگذاری روی داده تست شده باشند.
4. حالت خطا، داده خالی، لغو عملیات و retry بررسی شده باشند.
5. مستندات و نسخه هدف با واقعیت کد هماهنگ باشند.
6. محدودیت آزمون دستگاه واقعی صریحاً ثبت شود.

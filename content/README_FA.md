# راهنمای محتوای GitHub در MindUnlock

این پوشه منبع محتوای آموزشی عمومی برنامه است. همگام‌سازی آن مستقل از سرویس LAN ویندوز باقی می‌ماند.

## ساختار

- `manifest.json`: فهرست نسخه‌دار و نقطه ورود همگام‌سازی
- `library/`: فایل‌های فصل و محتوای آموزشی تأییدشده
- `inbox/`: فایل‌های ارسالی کاربران که هنوز باید در Pull Request بازبینی شوند

## قرارداد Manifest نسخه ۱

ریشه فایل باید شامل `schema_version: 1` و آرایه `items` باشد. هر ورودی شامل این فیلدهاست:

- `id`: شناسه پایدار و یکتا؛ پس از انتشار تغییر نکند
- `title` و `group_name`: عنوان و دسته
- `order_num`: ترتیب نمایش
- `path`: مسیر فایل داخل `content/library/`
- `format`: یکی از `json`، `md`، `markdown` یا `txt`
- `content_hash`: هش SHA-256 بایت‌های دقیق فایل UTF-8
- `updated_at`: زمان UTC در قالب ISO-8601
- `schema_version`: نسخه قرارداد ورودی (فعلاً ۱)

فایل JSON فصل باید یک شیء `chapter` و آرایه `items` داشته باشد. هر آیتم حداقل به `title` نیاز دارد و بهتر است `source_uid` پایدار، `type`، `content`، `order`، و در صورت نیاز `options`، `answer` و `explanation` نیز داشته باشد. این قرارداد با ساختار فصل‌های سرویس Windows سازگار نگه داشته شده است.

## انتشار تغییر

1. فایل را در `content/library/` اضافه کن؛ برای هر فصل شناسه و مسیر یکتا انتخاب کن.
2. SHA-256 را از محتوای نهایی فایل محاسبه کن؛ پس از محاسبه حتی یک فاصله یا newline را تغییر نده.
3. ورودی را به `content/manifest.json` اضافه یا همان ورودی را با حفظ `id` به‌روزرسانی کن.
4. Pull Request را بازبینی کن؛ فایل‌های `inbox/` تا زمان تأیید، محتوای فعال برنامه نیستند.

## ایمنی همگام‌سازی

برنامه قبل از واردسازی مسیر، پسوند، اندازه، ساختار و SHA-256 را کنترل می‌کند. فصل جدید و تغییر راه‌دور بدون تغییر محلی قابل انتخاب‌اند. تغییر محلی، تعارض دوطرفه و فصل محلیِ فاقد سابقه همگام‌سازی به‌صورت خودکار جایگزین نمی‌شوند. حذف ورودی از Manifest نیز داده محلی را حذف نمی‌کند.
